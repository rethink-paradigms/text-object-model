Dimension 04

Transclusion & Provenance

How do you include content by reference — and track where it came from?

❓

The Question

Transclusion is the killer app for stable addressing. It answers a simple question: can I include a paragraph from document A in document B, have it stay connected to the source, and survive edits at both ends? This is what quotation, copying, and cross-referencing merely attempt — they are ways people have had to imitate transclusion.

Coupled with provenance — tracking where every piece of text came from, what it was derived from, and who transformed it — transclusion becomes the mechanism for building a traceable, composable document ecosystem. The Text Runtime enables what no current system can: transclusion at the paragraph/sentence level with stable, verifiable references.

📡

The State of Transclusion Today

Transclusion exists today — but only at the document or section level, and only with fragile references:

Obsidian/Magma WikiLinks
Document/Section · Fragile
![[Page#Section]] — the most popular current implementation. Transcludes documents or sections. References break when the target page is renamed or the section heading changes. No stable identifier — the link is by filename/heading text. The Magma extension adds recursive expansion and header level adjustment but doesn't solve the identity problem.
Obsidian Block References
Block · Semi-stable
![[Note#^block-id]] — manual block anchors placed by the author. Survives within a single note but the ^block-id is local to the note, not globally unique. No protection against the note being renamed. Closest thing to what the Text Runtime enables, but without the infrastructure.
org-transclusion (Emacs)
Live-sync · Mature
Uses Emacs overlay modification-hooks to propagate edits bidirectionally between source and transclusion. Edit either copy — the other updates instantly. The text-clone library creates paired overlays where any modification to one is mirrored to the other. The most technically sophisticated transclusion implementation, but limited to Emacs.
BendScript Edges
Graph-native · v0.1
Transclusion as a typed edge (transcludes predicate) in a content-addressed document graph. Edges target span URIs like bend:#blk-1.spn-2. Edge types include cites, supports, contradicts, transcludes. The most expressive model, but still in v0.1.
"Transclusion is what quotation, copying and cross-referencing merely attempt: they are ways that people have had to imitate transclusion, which is the true abstract relationship that paper cannot show. Transclusion means that the same thing is knowably and visibly in more than one place." — Ted Nelson, Xanadu (1960s)

Transclusion in the Text Runtime

The Text Runtime enables transclusion that no current system can match: by UUID, at any granularity, with verifiable provenance.

How It Works

Document A contains paragraph #a3f2c9d1
  "The Text Runtime gives every sentence a permanent address."

Document B declares a transclusion:
  transclude: docA#a3f2c9d1

At render time:
  1. Resolve UUID → fetch node content from Document A
  2. Display the paragraph (optionally with source attribution)
  3. If Document A changes → Document B's view updates
  4. If paragraph is deleted → Document B shows orphan state

The reference is to a UUID, not a filename or position.
Renaming, reorganizing, or editing Document A doesn't break the link.

Three levels of transclusion:

Level 1 — Read-only display. The transcluded content is shown but cannot be edited in place. Changes must be made at the source. Safe, simple, sufficient for most use cases. What Obsidian and most current tools do.

Level 2 — Write-through editing. Editing a transcluded paragraph propagates changes back to the source. Dangerous but powerful — you can inadvertently edit content referenced elsewhere. The system must surface backlinks before committing edits. What org-transclusion does.

Level 3 — Bidirectional awareness. Both the source and the transclusion know about each other. Backlinks are first-class. Edits are committed with awareness of all contexts the content appears in. Shows "this paragraph is referenced by 3 other documents" before allowing destructive edits. This is the aspiration.

Text Provenance: Tracking Origins

Provenance answers: where did this text come from? Who wrote it? What was it derived from? What transformations were applied? Current approaches operate at three distinct levels — and the Text Runtime can unify them:

Cryptographic Content Provenance
C2PA 2.3 §A.7 · Encypher
Embeds provenance manifests in text using invisible Unicode characters (zero-width joiners, variation selectors). Encypher extends this to sentence-level attribution — each sentence individually authenticated. Survives copy-paste across browsers, email, messaging. Designed for copyright enforcement and quote integrity.
Epistemic Provenance for AI
Wire
Structural metadata attached to each retrieved chunk: source file, chunk position, ingestion time, typed relationships (elaborates, corroborates, contradicts, supersedes). Designed for AI agents to consume at inference time. "Most hallucinations are actually unfaithful attributions."
Source-to-Output Provenance
TROVE · GenProve
Academic benchmarks for tracing each sentence in AI output back to source sentences. Relationship classification: Quotation, Compression, Inference. Sentence-level granularity is the emerging standard for AI provenance.
PROV-O Ontology
W3C · trustgraph · kaos-content
Every transformation is an Activity that generates new Entities from existing ones. URI schemes track wasDerivedFrom, wasGeneratedBy, used relationships. Each node carries optional Provenance with source reference, page number, confidence score, extractor name.

The gap: All four levels are about attribution (who wrote what, where did this come from), not about structural addressing (how do I stably reference paragraph X). The Text Runtime provides the addressing layer that provenance systems can then annotate. Provenance becomes an overlay — node-id → provenance-record — attached via the same applicative mechanism as annotations and transclusions.

The Transclusion Edit Problem

This is the hardest unsolved problem in transclusion. If document A transcludes a paragraph from document B, and a reader of document A wants to edit it — what happens?

Obsidian's Approach
Read-only transclusion
You cannot edit transcluded blocks in place. You must navigate to the source, edit there, and the change propagates. Safe but creates friction. The "mother block / child block" model.
Roam's Approach
Editable everywhere
Blocks are interchangeable. Editing a transcluded block edits the source. Powerful but dangerous — you can inadvertently edit content referenced elsewhere, with no warning.
Text Runtime Recommendation
Explicit modes
Default: read-only. Transclusions are displayed but not editable. When editing is enabled, surface backlinks ("this block is referenced by 3 other documents") before committing. Offer both — but make the trade-off visible.
