Architectural Decisions

What we chose, what we rejected, and why — with sources.

The 8 Decisions

Decision 1
Content Lists (referential) over Embedded Content (buffer)
Chosen Content-as-reference model. Documents are lists of pointers to content objects with stable UUIDs.
Rejected Traditional text buffer model — edit a character buffer in place.
Sources Xanadu (2000): "Documents, versions and links are structures which point to content and use that content by reference." SiSU: "Object-centric document abstraction." BendScript: blocks with CIDs.
Risk Higher complexity than raw text editing. Mitigated by: the human surface stays clean (Markdown). The reference model is purely in the runtime layer.
Trade-off Gain: stable addressing, transclusion, provenance. Lose: simplicity of "text is a string — edit it in place."
Decision 2
UUID v7 (time-ordered) over sequential integers or HIDs
Chosen UUID v7 as the primary identifier for every node.
Rejected HIDs (hierarchical: break on move). Sequential integers (coordination problems). Content-addressed hashes (not human-friendly, require full content).
Sources Purple Numbers NID analysis (2001): HIDs "break or become incorrect as the site's content evolves" while NIDs "continue to point to the correct item." UUID v7 spec (RFC 9562, 2024).
Risk UUIDs not human-readable. Mitigated by: they never appear in the writing surface. Debug tools show label + UUID.
Trade-off Gain: global uniqueness, stability, B-tree friendly. Lose: human readability in debug contexts.
Decision 3
Sentence-level granularity (primary) over Paragraph-level or Character-level
Chosen Sentence as the primary addressing granularity. Paragraph-level UUIDs also exist. Sub-sentence uses character offsets within a sentence node.
Rejected Paragraph-level only (too coarse — can't annotate individual sentences). Character-level (UUID thrash — every edit creates new sub-nodes).
Sources Santhosh Thottingal (2026): six-stage HTML sentence segmentation. Hypothesis (2013): annotations use ranges for arbitrary spans. SiSU: paragraph-level with explicit note that sub-paragraph requires offsets.
Risk Sentence detection imperfect for bullet points, code, poetry. Mitigated by: best-effort parse; fall back to containing block if detection fails.
Trade-off Gain: right balance of stability and precision. Cost: sentence detection at parse time.
Decision 4
Applicative Overlays over Embedded Annotations
Chosen Annotations, tags, links, provenance stored separately and reference UUIDs. Never embedded in source text.
Rejected Embedded annotations (HTML-style <a href="..."> or embedded JSON in Markdown comments).
Sources Xanadu: "The xanalogical content link is not embedded. It is applicative — applying from outside to content which is already in place with stable addresses." W3C Web Annotation: SpecificResource pattern. Hypothesis.
Risk External annotations can be orphaned. Mitigated by: active_partial and orphan states with user-visible indicators.
Trade-off Gain: unlimited overlapping annotations from multiple agents. Lose: self-contained-ness of embedded annotations.
Decision 5
Dual Selectors (position + quote), reconciled at write time
Chosen Every annotation stores both TextPositionSelector (UUID+offset) and TextQuoteSelector (exact text + prefix/suffix). Reconciled at write time.
Rejected Single selector approach (position-only breaks on edit; quote-only is slow and ambiguous).
Sources W3C Web Annotation (2017): defines both selectors. Semiont (2025): "The two selectors are not independent guesses — they are reconciled at write time." "A no-overlap invariant rejects any annotation whose selectors disagree."
Risk Increased storage per annotation. Mitigated by: selectors are small. Reliability gain worth the cost.
Trade-off Gain: robust re-anchoring with fast path + fallback. Cost: storing two selectors + write-time reconciliation.
Decision 6
Cascading Re-Anchoring with Confidence Scores
Chosen 4-level anchoring: (1) exact UUID+offset, (2) character offset, (3) context-fuzzy (prefix+exact+suffix), (4) exhaustive fuzzy. Each returns confidence 0.0–1.0.
Rejected Single or two-level anchoring (insufficient for real-world content changes).
Sources Hypothesis Fuzzy Anchoring (2013): "To achieve robust reattachment of annotations we combine several approaches. We save the information about each target fragment in three different selectors."
Risk Strategy 4 can produce false positives. Mitigated by: confidence scores. Below 0.5, show warning.
Trade-off Gain: robustness. Cost: anchoring complexity. User sees confidence indicator; system handles complexity.
Decision 7
SQLite Storage (local-first) over Cloud Service or Custom Engine
Chosen SQLite as the backing store for node tree, annotations, and transclusions.
Rejected Xanadu enfilades (complex, no ecosystem). Cloud-only (no offline). JSON files (no query, no indexing, full reload).
Sources SiSU: uses SQLite FTS for full-text search. Our existing DB layer. FTS5 for text search. ACID transactions for edit safety. JSON functions for annotation payloads.
Trade-off Gain: local-first, free offline, fast startup. Lose: ability to query across all documents on a server (can sync SQLite when needed).
Decision 8
Format Plugin System (format-agnostic) over Markdown-only
Chosen Runtime defines a common object model. Format-specific parsers (Markdown, TXT, transcript, DOCX) map to this model. New formats implement a Parser interface.
Rejected Building only for Markdown and assuming it will generalize.
Sources SiSU (single abstraction → multiple output formats, 2006–2025). Santhosh Thottingal (HTML segmentation, 2026): different input formats need different parsing strategies.
Risk More work upfront. Mitigated by: Markdown is the only parser needed for v1. Interface defined; other parsers added incrementally.
Trade-off Gain: future-proofing and format flexibility. Cost: small upfront design cost for the parser interface.
