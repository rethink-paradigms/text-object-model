Build Plan

The engine — parsing, UUID assignment, storage, projection, annotations, transclusions, agent cursor — is built and tested. The remaining work is about what agents see and how they declare.

  • Handle the §N sentence marker → UUID resolution inside the tool, transparent to agents
  • File-watcher daemon integration for automatic re-ingestion
2
Discovery Interface
Planned
Give agents a way to understand what's in the corpus before they start a task. Not reactive search — proactive overview.
  • corpus_overview() — documents, formats, sizes, ingestion dates
  • annotation_landscape() — what's annotated, by whom, confidence distribution
  • open_questions() — orphan and active_partial annotations as signals of uncertainty
  • relationship_graph(doc_id) — what cites, derives from, or contradicts this document
  • topic_clusters() — structural clustering across corpus
3
Structured Read Brief
Planned
Augment project() to include epistemic state alongside text. The agent reads the document AND its context simultaneously.
  • projectAgentBrief(uuid) — full document + annotation summary + provenance edges + §N markers
  • Header block: ingestion metadata, annotation counts by status, prior references, derivation chain
  • Per-sentence annotation inlining: §3 gets confidence + agent + type annotations appended
  • Token-efficient format — prioritize signal density
4
Output Declaration
Planned
Let agents declare where their output came from using TROVE relationship types.
  • declare_output({ document, sentences: [{ sentence, type, source_uuid, source_sentence }] })
  • TROVE relationship types: quotation, compression, inference, composition, original
  • Stored as provenance annotations in SQLite
  • Future agents reading the output can trace every claim to its source
5
UUID Migration / Intent Protocol
Open Question
When an agent transforms text from one document into another, what happens to the UUID relationship? This is the deepest open design question.
❓

Open Design Questions

UUID migration on agent transformation. When an agent summarizes document A as document B, should B's sentences carry provenance edges to A's sentences? If so, should the agent declare this explicitly or can the runtime infer it? Explicit declaration is friction. Inference is fragile.
Minimum viable output declaration. If agents won't declare provenance for every sentence (too much friction), what's the minimum that provides value? Document-level "derived from" edge + key sentences flagged manually?
Discovery without search. The discovery interface is meant to let agents understand the corpus without querying. But what's the "right" amount of information to surface? Too much increases token cost. Too little leaves the agent uninformed.
Confidence decay over re-ingestions. When a document is re-ingested 5 times, an annotation that survived all 5 re-ingestions via fuzzy matching should probably carry a lower confidence than one that survived via exact match. How should confidence decay compound?
Daemon mode production readiness. Code exists. Needs integration testing with real file-watch scenarios: what happens when a file is deleted mid-ingest? When a directory is moved? When thousands of files change simultaneously?
